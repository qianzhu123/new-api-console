# 插件账号同步非阻塞设计

## 背景

插件点击“更新到本地并重新检测”后，会等待 `POST /api/auth/sync-account` 完整返回。后端在保存账号之后，仍在同一个请求中访问目标网站执行签到和状态检测。只要目标网站、DNS 或网络连接迟迟不结束，插件就一直显示“正在按网站地址和用户 ID 同步账号”，即使账号已经完整写入本地。

问题的根因不是本地保存失败，而是“本地持久化成功”和“远程签到/检测完成”被绑定成了同一个同步响应边界。

## 目标行为

- 后端完成账号匹配、更新或创建并成功写入本地配置后，立即向插件返回成功。
- 插件立即恢复按钮并显示“已更新现有账号到本地”或“已添加新账号到本地”。
- 已有账号的状态检测，以及新账号的一次签到和状态检测，继续执行，但改为后端后台任务。
- 目标网站缓慢、异常或不可访问时，不影响已经完成的本地保存，也不让插件保持加载状态。
- 后台任务完成后继续写入现有签到状态和状态缓存；控制台刷新账号或重新打开时读取最新结果。
- 不引入“检测超时即同步失败”的提示，因为同步成功的定义是本地账号已保存。

## 后端设计

提取独立函数处理保存后的远程工作：

- 输入为保存后的账号字典副本和 `created` 标记。
- 新账号先执行 `classify_checkin()` 并通过 `persist_account_checkin_result()` 保存签到结果。
- 所有账号执行 `fetch_public_status()`、`check_status()` 和 `set_status_cache()`。
- 后台异常只转换为状态缓存中的失败结果或安全结束，不回滚已经保存的账号。
- 后台函数不读取 `request`、不调用 `jsonify`，也不依赖 Flask 请求上下文。

`POST /api/auth/sync-account` 保留现有身份匹配顺序和账号保存逻辑。账号保存成功后，通过一个守护线程调度后台任务并立即返回：

- `ok: true`
- `created` / `updated`
- 已保存的公开账号信息和账号列表
- `detection_pending: true`
- 说明本地保存成功、后台检测已启动的 notes

接口不再等待 `classify_checkin()`、`fetch_public_status()` 或 `check_status()`。

为便于测试，后台调度封装为单独函数；测试可以替换调度器，确认请求已返回且远程检测没有在请求线程中执行。

## 插件设计

插件继续调用同一个同步接口，不需要设置长时间等待或把成功误报为超时。

收到成功响应后：

- 立即调用 `notifyQiandaoTabs()`，把已保存账号同步给打开的本地控制台。
- 新账号显示“已添加账号 #N 到本地，签到和检测正在后台执行。”
- 已有账号显示“已更新账号 #N 到本地，重新检测正在后台执行。”
- `finally` 正常恢复“更新到本地并重新检测”按钮。

插件不再根据同步响应里的 `result.session_valid` 判断本次保存是否成功，因为 `result` 属于后台检测结果，不再是即时响应的一部分。

## 并发与错误处理

- 每次成功保存只启动一个对应后台任务。
- 后台任务使用账号副本，避免后续请求修改同一个字典对象。
- 状态和签到文件继续使用现有锁与原子写入函数。
- 后台检测异常不修改账号登录数据，不删除账号，不把同步响应改为失败。
- JSON 解析、身份匹配、账号字段校验或本地保存失败仍同步返回错误，插件显示“更新失败”。

## 测试

后端测试覆盖：

- 已有账号保存后接口立即返回 `detection_pending=true`，并将后台任务交给调度器。
- 新账号保存后接口立即返回，调度参数包含 `created=true`。
- 被替换为会阻塞或抛错的远程检测函数不会在请求线程中执行。
- 后台工作函数仍按既有规则执行新账号签到、状态检测和缓存写入。

插件静态回归测试覆盖：

- 成功提示明确区分“已保存到本地”和“后台检测中”。
- 不再从即时响应的 `result.session_valid` 推断同步成败。
- 仍保留 `finally` 恢复按钮。

验证命令：

- `python -m pytest -q tests/test_accounts.py`
- `node --check tools/qiandao_account_import_extension/popup.js`
- `python -m py_compile app.py`
- `python -m pytest -q`

## 非目标

- 不改变按“网站地址 + `new_api_user`”优先匹配账号的规则。
- 不取消新账号首次签到或所有账号状态检测。
- 不增加任务队列、数据库或跨进程作业系统。
- 不保证插件弹窗关闭后主动弹出后台检测完成通知；最终结果由本地缓存和控制台后续刷新读取。
